# 本地 AI 与 Neo4j 知识查询

知识原文和关系保存在真实 Neo4j 的 `hydroponic-real` 范围。问答快照、收藏、探究记录和日志保存在业务数据库，不能作为图谱的替代查询源。Neo4j 离线时知识接口返回 503。

本机已安装 Ollama `qwen3.5:4b`。Docker 后端通过 `HYDRO_OLLAMA_DOCKER_URL`（默认 `http://host.docker.internal:11434`）访问；原生 Python 使用 `HYDRO_OLLAMA_URL`（默认 `http://127.0.0.1:11434`）。默认模型由 `HYDRO_LLM_MODEL` 指定。页面可刷新连接状态并选择已经安装的模型，不调用云端服务、不自动下载模型。

查询流程：

1. 后端使用参数化 Cypher 按关键词、中文短语及常用同义表达检索资料，最多返回 6 条；图谱直接遍历数据库中对应关系。用户输入和模型输出都不会执行为 Cypher。
2. 本地 AI 只接收来源原文、真实性标记以及提问时的设备采样上下文。空传感器值原样保留，过期采样显式标记，不混入旧茬次记录。
3. Ollama 使用 JSON 输出，后端校验结构与引用编号。当前 Ollama 的语法编译器不兼容部分嵌套、有长度约束的 JSON Schema，因此在应用层执行严格验证。
4. 回答没有来源、模型不可用、超时或引用无效时，页面给出明确结果。无来源不会生成农艺诊断；模型失败返回 503，用户可主动切换为仅查询资料。
5. 回答保存模型名称、时间、原文、图谱、环境和真实性标记快照。收藏及探究记录使用回答 ID 读取当次快照，不重新检索。编辑资料会保留历史版本并恢复为待核验。

接口：`GET /api/ai/status`、`GET /api/knowledge/status`、`GET /api/knowledge/graph?q=…`、`POST /api/ask`、`POST /api/knowledge`、`PUT /api/knowledge/{id}`。`/api/ask` 的 `mode` 为 `local_ai` 或 `neo4j_graph`；设备可留空。知识录入和编辑限教师/管理员，普通查询向所有已登录角色提供。

本次显式导入了项目 MQTT 文档的 4 个原文段落，每条保存文件路径和 SHA-256，标记为“项目资料、待核验”。导入工具 `python -m backend.import_project_knowledge --root <项目目录>` 按固定 ID 去重，不覆盖已有编辑，也不在服务启动时播种。农艺教材、病害诊断等资料仍需按实际来源录入；设备文档不能代替种植依据。

软件验证涵盖真实 Neo4j 写入/修改/读回、无来源和离线处理、错误引用拒绝、跨账户保存限制、旧茬次隔离，以及浏览器中的真实 Ollama 问答。结构与引用校验不能保证模型对原文的理解完全正确，页面始终保留待核验标记与可查看的原文。
