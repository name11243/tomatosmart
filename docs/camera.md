# 本机与远程摄像头

成熟度页面的“拍照识别”使用浏览器本机摄像头；“远程摄像头”连接 ESP32-P4 的照片接口。最低置信度沿用页面选项，默认 65%。

远程接入依据用户提供的 `01_WiFi_SCAN.zip` 中 `components/http_snap_server/http_snap_server.c`、`components/wifi_service/wifi_service.c` 和 `main/app_features.c`：默认热点 IP 为 `192.168.4.1`，照片地址为 `http://192.168.4.1/image`；使用设备的局域网 IP 也可以。填写纯 IP 或设备根地址时自动补上 `/image`。这是约 20 秒更新一次的最新照片接口，固件没有提供连续视频、主动拍照接口或采集时间戳。

运行本系统的电脑必须能访问摄像头 IP；照片由后端读取，所以浏览器不会直接跨域访问设备。当前支持 HTTP/HTTPS IPv4 照片地址，不接受本机回环、链路本地地址、文件协议或重定向。界面可连接、预览、手动刷新、断开、识别或保存当前照片。连接失败会清除旧预览并报错，预览本身不写入生长档案。

固件的自动采集前提是 Wi-Fi STA 已联网、ESP-Hosted 通信正常、HTTP 与 UVC 均就绪。仅连接设备自身热点不能满足 STA 联网条件，可能没有新照片。页面的“本次获取”是平台取得照片的时间，实际采集时间标记为未知。平台只调用 GET /image，不修改设备的 `/backend-config`，也不向设备 `/upload` 写入图片。

登录会话保存在本机业务数据库独立 sessions 表中，保留原来的八小时有效期。数据库仅保存随机令牌的哈希；更换密码或切换本机角色登录模式会使原会话失效，退出登录会撤销会话。有效会话可跨后端重启继续使用。

前端收到 401 时，在原有免密角色模式下恢复当前角色并重试被拒绝的请求一次；密码模式仍要求重新登录。已拍照片暂存在当前页面内存中，已上传成功的照片复用原照片编号，避免因后续识别登录失败重复上传。刷新或关闭页面会释放尚未保存的照片。

验证命令：`node --test tests/auth-recovery.test.mjs`；在隔离临时数据库的容器内运行 `python tests/verify_camera.py`。测试不向真实档案写入测试照片。
